# gitacre 1.1.0-beta

Automatic updates, plus fixes for a hang that could disable refreshing for an entire session and a bug that hid repositories git could not read.

## Update yourself once, by hand

This is the first build containing an updater, so it cannot install itself over 1.0.0-beta. Download it, replace the app in `/Applications`, and later releases will offer themselves in the panel.

## Automatic updates

gitacre now checks for new releases and installs them, using [Sparkle](https://sparkle-project.org). Updates are downloaded over HTTPS and rejected unless they carry both a valid EdDSA signature from the release key and a valid Developer ID signature.

Nothing is sent about you or your machine: the check is a request for a static feed, and the system profile Sparkle can attach is disabled.

The whole flow is shown inline in the panel rather than in separate windows, so the menu-bar app stays a menu-bar app. Settings › General gains an **Updates** section with automatic checks, optional background downloads, the current version, and a manual check.

## Fixes

**A repository with many changed files could hang gitacre until you relaunched it.** Output from `git` was only read after the command finished, but a pipe holds 64 KiB before it blocks, so any command producing more than that waited forever for a reader while gitacre waited forever for the command. About 1,100 changed files was enough to trigger it, and a repository-wide reformat did it easily. Because the hang happened inside a refresh, the in-progress flag was never cleared and every later refresh was skipped: the spinner ran forever and the 60 second timer stopped doing anything.

**Repositories git could not read disappeared from the list.** If `git status` failed, the repository was dropped with nothing reported. The common cause is `detected dubious ownership`, which git raises for repositories on external drives, on shared machines, or touched by `sudo`. They now appear in an **Unreadable** section at the top of the list, showing git's own explanation on hover, and count towards the menu-bar badge. A repository whose linked worktree alone failed keeps the worktrees that did work.

## Performance

**Scanning is about four times faster.** Repositories were scanned strictly one after another, though nearly all of that time was spent waiting on `git` rather than working. Independent repositories are now read side by side. Measured across 50 repositories: 2.3s before, 0.5s after.

**Scrolling no longer reads from disk.** Repository icons were read and decoded from disk twice per row every time the list redrew, on the main thread. They are now decoded once and kept until the next scan.

## Requirements

macOS 14 or later, Apple silicon or Intel.
